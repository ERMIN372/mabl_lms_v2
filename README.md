# МАБЛ · LMS-платформа

LMS-сайт **Международной академии бизнес лидерства (МАБЛ)** на React + Vite +
TypeScript. Визуальная айдентика строго по бренд-гайду `MABL_GUIDE.pdf`:
цвета Нефть / Океан / Мудрость, герб и логотип академии, шрифт TT Rationalist,
академический премиум-минимализм.

## Технологии

- **React 18** + **TypeScript** (strict)
- **Vite 5**
- **React Router 6**
- **Tailwind CSS 3** (брендовые токены в `tailwind.config.js`)
- **Бэкенд:** serverless-функции Vercel (`api/*`) + PostgreSQL Neon;
  весь контент создаётся из админ-панели и хранится в БД

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
npm run preview  # предпросмотр прод-сборки
```

### Доступ администратора

Приложение работает только с реальным бэкендом и БД (Neon). После
инициализации БД (`POST /api/admin/db/init` или кнопкой в разделе «База
данных») заводится единственный стартовый аккаунт — администратор.
Логин задаётся переменной окружения `ADMIN_EMAIL` (по умолчанию
`admin@mabl.ru`), пароль — `ADMIN_PASSWORD`.

Пароля по умолчанию нет намеренно: константа в открытом коде означала бы, что
доступ к админке знает каждый, кто видел репозиторий. Если `ADMIN_PASSWORD` не
задан, инициализация сама сгенерирует случайный пароль и покажет его в ответе
(и в уведомлении админки) — **один раз**: в базе хранится только хэш.

Никакого стартового контента база не получает: программы, события, новости,
материалы, опросники, участники и заказы создаются из админ-панели.

> Если база работала на версиях до июля 2026, в ней могли остаться записи
> старых демо-сидов (демо-курсы, заказы, участники, уведомления, материалы,
> опросники, аккаунт `demo@mabl.ru`). Раздел админки «База данных» → «Убрать
> демо-данные» сначала показывает найденное, а удаляет только по кнопке —
> записи, созданные администратором, не затрагиваются. Сам код демо-данных
> больше не создаёт ни при инициализации, ни при обращении к пустому разделу.

> После первого входа смените пароль в разделе «База данных» админ-панели.
> Вход выдаёт токен сессии; все операции администрирования (`/api/admin/*`
> и любые изменения данных) требуют этого токена. Задайте собственный
> секрет подписи токенов переменной окружения `AUTH_SECRET`.

### Платежи · ЮKassa

Оплата программ идёт только через ЮKassa: демо-оплаты в приложении нет.
Серверные ключи задаются переменными окружения на Vercel (во фронтенд они не
попадают):

1. В личном кабинете ЮKassa (Магазин → Интеграция) возьмите `shopId` и секретный
   ключ и пропишите `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`.
2. В настройках ЮKassa укажите URL для уведомлений (webhook):
   `https://<домен>/api/payments/webhook` — события `payment.succeeded` и
   `payment.canceled`.
3. Пока ключи не заданы, эндпоинты оплаты отвечают 503 и купить программу нельзя.

Поток оплаты (всё проверяется сервером, клиент не диктует ни цену, ни доступ):

- `POST /api/payments/create` — требует токен сессии: заказ (`pending`)
  привязывается к пользователю из токена, цена берётся из БД, платёж создаётся
  в ЮKassa с ключом идемпотентности; в ответ — ссылка на платёжную форму.
- Пользователь оплачивает на стороне ЮKassa и возвращается на
  `/checkout?course=…&order=…`, где статус подтверждается через
  `GET /api/payments/by-order/<id>` (перезапрос платежа в ЮKassa; заказ виден
  только своему владельцу и администратору).
- `POST /api/payments/webhook` — серверное уведомление: статус заказа в БД
  переводится в `paid` / `refunded` (тело не доверяется — платёж перезапрашивается
  по id).
- `GET /api/payments/config` — отдаёт, настроена ли боевая оплата.

Проверить готовность можно тестовым магазином ЮKassa (тестовый `shopId`/ключ).

### Регистрация слушателей

Аккаунт нужен, чтобы оплатить программу: покупатель регистрируется сам на
`/login` (вкладка «Зарегистрироваться», `POST /api/auth/register`) — заводится
аккаунт роли `student`, он же появляется в разделе админки «Участники».
Администратор по-прежнему может создать аккаунт вручную в разделе
«База данных».

Восстановление пароля (`POST /api/auth/recover`) пока только подтверждает приём
заявки: отправка писем не подключена, пароль меняет администратор.

### Заявки на поступление

На странице программы (`/programs/<id>`) кнопка «Оставить заявку» ведёт к форме
в секции «Поступление»: имя, телефон, e-mail, комментарий и обязательное
согласие на обработку персональных данных. Форма доступна и гостю, и
авторизованному слушателю (у второго имя и e-mail подставляются из профиля).

- `POST /api/applications` — публичный приём заявки. Сервер проверяет контакты,
  сам проставляет статус `new` и дату, а если запрос пришёл с токеном сессии —
  связывает заявку с аккаунтом.
- Заявки хранятся в общей таблице `content` (коллекция `applications`) и видны
  приёмной комиссии в админ-панели: `/admin/applications`
  (`GET/PUT/DELETE /api/admin/applications`). Статусы: новая → в работе →
  зачислен / отклонена.

### Доступ к материалам курса

Материалы программы (уроки, SCORM-тренинги) открываются только авторизованному
слушателю, у которого в БД есть **оплаченный** заказ на эту программу. Права
доступа отдаёт сервер — `GET /api/me/courses` по токену сессии; в браузере
доступ не выдаётся и не хранится. Гость и слушатель без оплаты видят только
описание программы, состав модулей и стоимость. Программы с ценой 0 открыты
любому авторизованному слушателю.

Администратор может открыть доступ вручную — создав в разделе «Заказы» заказ
на нужного участника со статусом «оплачен» (например, при оплате по счёту).

**Как заказ находит владельца.** Сначала по `userId` заказа, а если совпадения
нет — по e-mail аккаунта: подхватываются заказы, выписанные на карточку
участника с тем же адресом, и заказы, оплаченные онлайн на этот e-mail. Это
нужно, когда карточку в «Участниках» завели руками до того, как человек
зарегистрировался: id карточки и id аккаунта тогда разные, а раньше такой
оплаченный заказ доступа не давал.

**Если доступ «пропал», хотя заказ оплачен.** Почти всегда дело в сессии, а не в
заказе: профиль хранится в браузере бессрочно, токен — 30 суток. При запуске
приложение сверяет сессию (`GET /api/me/session`) и продлевает её; если токен
мёртв, вход честно сбрасывается с сообщением «Срок сессии истёк», а не тихо
закрывает оплаченные программы. Сбой сети или базы доступ больше не отзывает —
показывается прошлый список с пометкой, что проверить не удалось.

> ⚠️ Обязательно задайте `AUTH_SECRET`. Без него подпись токенов выводится из
> `DATABASE_URL`: смена строки подключения (ротация пароля Neon, переход
> pooled ↔ direct, разные значения в prod и preview) разом делает
> недействительными все сессии — у всех слушателей доступ «обнуляется» до
> повторного входа. В логах функции при этом есть предупреждение `[auth]`.

Повторно оплатить уже открытую программу нельзя: `POST /api/payments/create`
отвечает 409, если по ней уже есть оплаченный заказ.

## Новости из Telegram-канала

Раздел «Новости» автоматически подтягивает публикации (текст + изображения) из
публичного Telegram-канала академии. Источник — веб-превью `t.me/s/<канал>`,
поэтому бот и токен не нужны — достаточно, чтобы канал был **публичным**.

Настройка (переменные окружения проекта на Vercel):

| Переменная | Назначение |
|------------|------------|
| `TELEGRAM_CHANNEL` | Публичный `@username` канала (можно без «@» или ссылкой) |
| `DATABASE_URL` | Подключение к Neon (новости хранятся в таблице `news`) |

Как это работает:

- **Cron на Vercel** (`vercel.json` → `crons`) раз в сутки (06:00 UTC) дёргает
  `GET /api/news/sync`, который читает последние посты канала и делает
  идемпотентный upsert в таблицу `news` (id вида `tg-<канал>-<id поста>` —
  повторы не дублируются, отредактированные посты обновляются).
- **Кнопка «↻ Обновить из Telegram»** в `/admin/news` запускает ту же
  синхронизацию вручную (`POST /api/news/sync`).
- Публичный раздел `/news` и API `GET /api/news` отдают новости из БД,
  отсортированные по дате публикации; обложки постов показываются на карточках
  и на странице новости.

> Тариф Vercel Hobby разрешает cron-задачи только раз в сутки, поэтому расписание
> стоит на 06:00 UTC. Для более частого обновления используйте кнопку «Обновить
> из Telegram» в админке или тариф Pro (там можно вернуть, например, `0 * * * *`).

Новости, созданные вручную в админ-панели (`source = manual`), и импортированные
из Telegram (`source = telegram`) живут в одной таблице и не конфликтуют.

## Деплой на Vercel

В репозитории есть `vercel.json` (framework: vite, SPA-rewrites). Варианты:

1. **Через дашборд:** импортируйте репозиторий на vercel.com → Vercel сам
   определит Vite. Build: `npm run build`, Output: `dist`.
2. **Через CLI:**
   ```bash
   npm i -g vercel
   vercel        # preview-деплой
   vercel --prod # продакшен
   ```

SPA-роутинг покрыт rewrite-правилом на `index.html`.

| Переменная | Назначение |
|------------|------------|
| `DATABASE_URL` | Подключение к Neon PostgreSQL (обязательно) |

## SCORM-пакеты

Пакеты можно публиковать двумя способами.

**1. В репозитории (основной, бесплатный).** Пакет лежит в `public/scorm/<id>/` и
раздаётся Vercel как статика: без serverless-функций и облачного хранилища, а
значит без лимитов на операции и без риска приостановки. Как добавить:

1. распаковать `.zip` в `public/scorm/<id>/` (`id` — латиницей, через дефис);
2. добавить запись в `src/data/scormPackages.ts` (id, название, точка входа из
   `imsmanifest.xml` — обычно `res/index.html`, число файлов);
3. закоммитить. После деплоя пакет появится в админке («SCORM-пакеты» →
   «Пакеты в репозитории»), откуда из него создаётся курс.

Экспорт iSpring иногда кладёт скрипты с «обрезанным» расширением (`output.min.j_`
вместо `output.min.js`), хотя `index.html` запрашивает обычные `.js`. Тогда ни один
скрипт плеера не грузится и курс показывает пустой экран. Это чинится автоматически
при сборке (`scripts/normalize-scorm.mjs`, запускается как `prebuild`) — руками
переименовывать ничего не нужно.

Пути `/scorm/*` исключены из SPA-перезаписи в `vercel.json`: отсутствующий файл
пакета отдаёт честный 404, а не HTML приложения со статусом 200 — иначе поломка
выглядит немым пустым экраном.

**2. Загрузкой через админку (Vercel Blob).** Файлы грузятся в Blob-хранилище и
отдаются через прокси `/scorm-store/<id>/...`. Удобно, но расходует лимиты плана:
на бесплатном Hobby это 2000 «advanced operations» в месяц, при превышении Vercel
приостанавливает хранилище целиком. Раздача адреса файлов берёт из метаданных в БД
и операций не тратит — расходуется в основном сама загрузка (≈ по одной операции
на файл пакета).

Кнопка «Диагностика» у загруженного пакета проверяет на сервере, все ли его файлы
реально отдаются, и показывает проблемные с HTTP-статусом.

## Файлы учебных материалов

К материалу в админ-панели (`/admin/materials/<id>`) можно приложить файл —
презентацию, PDF, шаблон. Файл грузится из браузера напрямую в Vercel Blob
(тот же механизм, что у SCORM-пакетов: прямая загрузка обходит лимит тела
запроса Vercel в 4.5 МБ), в БД сохраняются его адрес, имя и размер:

- `POST /api/materials/blob-upload` — авторизация загрузки: права
  администратора проверяются по токену сессии из `clientPayload`, путь
  ограничен префиксом `materials/`.
- `GET /api/storage/upload-preflight` — общий преflight для всех разделов,
  которые грузят файлы: подключено ли хранилище и каким способом
  авторизуется запись (`scorm/upload-preflight` оставлен как синоним).
- Поле «Объём» заполняется автоматически по размеру файла.
- При замене или откреплении файла, а также при удалении материала старый
  объект удаляется из Blob — иначе он остался бы в хранилище навсегда.

На странице материала кнопка «Скачать материал» ведёт на этот файл. Если файл
не приложен, кнопки нет — материал читается прямо на странице.

## Если демо-данные появляются снова

Текущий код не создаёт никакого стартового контента: ни при инициализации базы,
ни при обращении к пустому разделу. Но в версиях до конца июля 2026 сервер
заливал демо-сиды (курсы, заказы, участники, уведомления, материалы, опросники,
аккаунт `demo@mabl.ru`) в **пустую** коллекцию при первом же запросе к ней —
поэтому на старом коде демо-данные восстанавливались сами после каждой уборки и
каждого деплоя.

Если демо-записи возвращаются, проверьте по порядку:

1. **Какая ветка деплоится.** Vercel хранит Production Branch в настройках
   проекта (Settings → Git → Production Branch) и НЕ меняет её вслед за
   изменением ветки по умолчанию в GitHub. Если там осталась ветка со старым
   кодом — прод продолжает заливать сиды. Ветка должна совпадать с той, куда
   вливаются рабочие PR.
2. **Остатки в базе.** Админка → «База данных» → «Убрать демо-данные» →
   «Проверить»: показывает найденные демо-записи по известным id, удаление —
   отдельной кнопкой. Если самого блока в админке нет, значит задеплоен старый
   код — см. пункт 1.
3. После уборки на актуальном коде записи больше не появляются: в серверном
   коде не осталось ни одного места, которое пишет контент без действия
   администратора (единственное исключение — импорт новостей из Telegram по
   расписанию, если задан `TELEGRAM_CHANNEL`).

## Что осталось подключить

- Хостинг видео для видео-уроков (SCORM-пакеты уже работают на клиенте).
- Лицензионные файлы шрифта TT Rationalist в `public/fonts/`.
- Серверное сохранение ответов опросов, записей на события и прогресса SCORM
  (сейчас прогресс хранится в localStorage браузера).
